# M2 Native Capture Foundations Status

**Status:** Windows and portal/PipeWire contract foundations are implemented; native C++ conformance compilation passed in WSL and an Ubuntu 22.04 container. Windows runtime, user-authorized Wayland runtime, GPU soak, and optical exit gates still require their respective reference machines.

## Implemented

- fixed-capacity capture/decoder surface pool with RAII capture leases;
- per-frame CopyLedger validation binds every owned surface to an evidenced completion/recycle path; direct aliasing is rejected without profiler proof;
- provider-neutral capture, input, render, cursor, coordinate, and presentation contracts;
- one-slot presentation coordination that retains each opaque native submission until its completion fence, or an explicit provider quiesce during recovery;
- real localhost UDP adapter and exact-codec loopback application;
- H.264 Annex-B inspection and conservative dependency planner;
- baseline policy forbidding B-frames, lookahead, and deep provider queues;
- Windows DDA capture/copy/metadata/access-loss probe;
- Windows Graphics Capture support probe;
- Media Foundation hardware H.264 encoder smoke probe: hardware-only asynchronous-MFT event driving, one synthetic D3D11 NV12 DXGI surface through a DXGI device manager, required low-latency CodecAPI negotiation, bounded drain, and structural H.264 validation (Annex-B or `MF_NALU_LENGTH_INFORMATION`) that rejects B-slices and requires an IDR; it is not a capture-to-encode or performance result.
- D3D11 visible viewer-path probe: synthetic NV12 source → D3D11 video processor → flip-discard swap chain, with frame-latency pacing, an event-query completion proof, and explicit tearing capability handling; it deliberately does not decode a real H.264 stream or measure scanout latency.
- guarded `SendInput` probe that performs no injection unless explicitly requested;
- service/per-user-agent and secure-desktop privilege boundaries encoded in the shared policy;
- real FFmpeg H.264 encode/decode fallback probe;
- portal-authorized Linux Wayland session state machine: capture-only and capture-and-control selection, RemoteDesktop/libei capability refusal, PipeWire stream identity, format/epoch changes, revocation/cancellation cleanup, and bounded owned-surface import;
- CMake native build with warnings treated as errors on Windows and Linux.

## Architecture experiment harnesses

- `latencydesk_win_capture_benchmark` is EXP-01’s same-adapter DDA/WGC ownership probe: a fixed three-slot D3D11 BGRA→NV12 pool, explicit `D3D11_QUERY_EVENT` completion proof, bounded capture lease, and JSON telemetry. It deliberately does **not** call an encoder, so it cannot rank backends until paired target-machine capture-to-encoder evidence exists.
- `scripts/codec_quality_benchmark.py` is EXP-03’s deterministic IDE/terminal/browser corpus probe. It compares H.264 4:2:0 and 4:4:4 output bytes and text-pixel reconstruction metrics, rejects B-frames, and reports batch timing only. It does not promote 4:4:4, ROI, or refinement.
- `scripts/transport_benchmark.py` is EXP-02’s bounded report adjudicator. It accepts only real QUIC and native WebRTC candidate evidence with matching impairment profiles; it rejects lost/reordered discrete input, unbounded memory, failed recovery, or absent required connectivity. It is not a transport implementation.
- `latencydesk_linux_pipewire_import_probe` is EXP-04’s fail-closed capture prerequisite probe. It records an authorized ScreenCast stream’s negotiated SPA tuple and immediately requeues every borrowed PipeWire buffer; encoder import remains deliberately disabled, so every result has `encoder_import_attempted: false` and `promotion_gate_passed: false` rather than claiming DMA-BUF direct import.

Run the executable experiments on their target systems:

```powershell
.\build\native\Release\latencydesk_win_capture_benchmark.exe --backend dda --duration-seconds 1800
.\build\native\Release\latencydesk_win_capture_benchmark.exe --backend wgc --wgc-monitor-interop --duration-seconds 1800
python scripts\codec_quality_benchmark.py --encoder h264_nvenc --width 1920 --height 1080 --frames 600 --fps 60
```

```bash
./build/native/latencydesk_linux_pipewire_import_probe
python3 scripts/transport_benchmark.py --quic-result quic.json --webrtc-result webrtc.json
```

These commands require their stated Windows/Wayland runtime and provider prerequisites. This workstation’s WSL/container builds prove compilation and noninteractive contracts only; they do not substitute for a Windows SDK build or a user-authorized Wayland portal session.

## Executed local evidence

The reproducible evidence below comes from WSL and an Ubuntu 22.04 container; neither supplies a Windows SDK, a GPU reference path, or a user-authorized Wayland compositor session. The following gates were executed:

```bash
cmake -S native -B /tmp/latencydesk-native-container -G 'Unix Makefiles'
cmake --build /tmp/latencydesk-native-container
ctest --test-dir /tmp/latencydesk-native-container --output-on-failure
/tmp/latencydesk-native-container/latencydesk_linux_pipewire_import_probe --help

python3 scripts/static_validate.py
python3 scripts/source_sanity.py
```

Observed evidence:

- native protocol and ownership conformance: pass;
- Ubuntu 22.04 PipeWire/GIO native build: `-Wall -Wextra -Wpedantic -Werror` pass;
- container CTest: 5/5 pass, including the noninteractive PipeWire probe CLI smoke test;
- unprivileged container runtime: the probe fails closed with `status: "session_bus_unavailable"` and `promotion_gate_passed: false`;
- WSL fallback build without PipeWire development packages: 4/4 CTest pass and no PipeWire target is emitted;
- parser/reference/static gates: pass.
- current Windows encoder-probe revision: `static_validate.py` and `source_sanity.py` pass; this workstation lacks MSVC and the Windows SDK, so its native build, `--help` CTest, and device runtime remain target-machine gates.

The FFmpeg times are batch wall-clock measurements. They are **not** per-frame hardware latency and are not an AnyDesk comparison.

A release may not mark M2 green until all of the following are attached as artifacts:

1. Windows CI compilation of every native target;
2. DDA and WGC results for the selected OS/GPU/driver matrix;
3. 1080p60 and 1440p120 capture → hardware encode → network → decode → present traces;
4. a 30-minute soak showing bounded queue depth and stable memory;

6. packet-loss recovery proving no dependent P-frame is decoded after a gap;
7. optical screen-to-screen and input-to-photon measurements.

## Gate interpretation

The M2 implementation proves that the native boundaries and executable probes exist. It does not yet prove Windows runtime compatibility, hardware latency, 120 Hz performance, or superiority over any competitor. Those claims remain blocked by the target-machine gate.
